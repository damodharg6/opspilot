The first engineer on the incident is an agent.

When an alarm fires, OpsPilot reads logs, metrics and recent deploys through read-only tools, then writes a root-cause report where every piece of evidence is copied from real tool output. It never changes production. A human acts.

    How it works
    
        
    From alarm to stored report
    
        
    Stateless services around one Postgres. Every box scales out on its own.
    
      
    
      
      
      
        
    1. 1
      Alarm in. The API checks a shared secret, inserts the incident with ON CONFLICT DO NOTHING (one open incident per alarm) and answers 202 immediately.
      2. 
        
    2. 2
      Claim. Any worker takes the oldest job with FOR UPDATE SKIP LOCKED and a lease. Workers never block each other or take the same job.
      3. 
        
    3. 3
      Investigate. The model calls read-only tools inside hard budgets for tool calls, tokens and wall-clock time. Tool output is wrapped as untrusted data.
      4. 
        
    4. 4
      Ground. Every evidence snippet must appear in real tool output; anything else is dropped and confidence goes down.
      5. 
        
    5. 5
      Store. The report is written only if this worker still holds the lease (fencing), so a slow, expired worker can't overwrite a newer attempt.
      6. 
      
    
    
    

    
    
    
      
    
        
    Engineering
    
        
    Built like production, not like a notebook
    
      
    
      
    
        
    Postgres as the queue
    Async API + SKIP LOCKED claims, leases, fencing and retries with backoff. One fewer system to run; swapping to SQS touches one file.
    opspilot/db/queue.py
    
        
    Budgets in code
    Tool calls, tokens and time are enforced by the loop, not requested in a prompt. When a budget runs out the model must answer with what it has.
    opspilot/agent/investigator.py
    
        
    Grounding check
    Hallucinated evidence is the worst failure for an on-call tool. Snippets not found in tool output are removed before the report is saved.
    opspilot/agent/grounding.py
    
        
    Read-only MCP tools
    Whitelisted query language, schema-validated inputs, capped output, secret redaction. Stateless streamable HTTP, local or AWS backends.
    mcp_servers/
    
        
    Any LLM
    One provider layer for OpenAI-compatible APIs, with its own retry policy and token accounting. Switching model is a config change.
    opspilot/llm/
    
        
    Evals gate CI
    Eight staged scenarios with ground truth. Live runs record fixtures; CI replays them offline and fails if accuracy drops.
    evals/
    
      
    
    
    

    
    
    
      
    
        
    AI roadmap · system design
    
        
    Where AI plugs in next, without a rewrite
    
        
    Each step adds a component behind an interface that already exists: the provider layer, the MCP tool gateway, or the Postgres store.

    NextRemember & route
    
          
      
            
    • Model routing: small fast model first, escalate on low confidence (provider layer)
      • 
            
    • Incident memory: past reports as embeddings in pgvector, a similar_incidents tool (same Postgres)
      • 
            
    • Runbook retrieval: an MCP server over the team's runbooks (tool gateway)
      • 
          
    
        
    
        
    
          
    LaterAct & observe
    
          
      
            
    • Human-approved actions: rollback or restart proposed in Slack; the agent stays read-only
      • 
            
    • Agent observability: OpenTelemetry spans per tool and model call; cost and accuracy dashboards
      • 
            
    • Continuous evaluation: every prompt or model change runs the live suite

    Run it
    
        
    Five commands to a live demo
    
      
    
      
    
        
    # clone, configure an LLM key (Groq/Gemini free tiers work)
git clone https://github.com/damodharg6/opspilot && cd opspilot
cp .env.example .env
make install
make demo-history && make up      # db, shop, 3 MCP servers, api, workers
make showcase                      # this site + live runs on :8090
    
        
    
          
    Live mode. Opened from make showcase, every demo gets a Run live button that stages the incident on your machine and streams the investigation here.
    
          
    Refresh the recordings after a prompt or model change with make record-demos.
